# Cheker

Мониторинг нод Remnawave и автоматическая смена IP доменов в Cloudflare при блокировке.

- Опрашивает ноды Remnawave. Если у ноды `isConnected` стал `false`, шлёт в Telegram «нода offline». Когда нода вернётся, шлёт «нода снова online» и сколько она не работала.
- Следит за **скоростью** каждой ноды. IP домена проверяется **только когда у его ноды упала скорость**. Связь ноды и домена: адрес ноды в Remnawave совпадает с доменом (или IP) во вкладке «Домены».
- После падения скорости текущий IP проверяется через **Latency Lab** 3 раза с интервалом 30 минут:
  - все 3 раза в бане → A-запись в Cloudflare меняется на следующий доступный IP из списка домена, и приходит уведомление;
  - хоть раз доступен → проверка останавливается, и приходит уведомление «скорость упала, но IP не в бане — с нодой что-то не так».
- Основной источник проверки — Latency Lab: смотрим проверку «с провода» (wire), и если по проводу IP недоступен, IP считается заблокированным. Дополнительный источник — bschekbot (bsbord.com): TCP через мобильных операторов. Он выключен по умолчанию и включается в «Настройки → Источники».
- При добавлении домена его текущий IP (A-запись в Cloudflare или DNS) определяется сам. Адреса новых нод сами появляются во вкладке «Домены».
- Все токены и адреса (Remnawave, Cloudflare, Telegram, Latency Lab) задаются в панели: «Настройки → Интеграции».
- IP можно проверить и сменить вручную из панели.
- Веб-панель на React (ПК и мобильная версия), тёмная тема, вход по паролю из `.env`.

## Подготовка

Все токены ниже можно ввести в панели («Настройки → Интеграции») после первого входа. Там же есть кнопка «Проверить» для каждой интеграции. В `.env` обязательны только `APP_PASSWORD` и `PANEL_DOMAIN`.

1. **Cloudflare.** Подходят оба вида токенов:
   - **токен пользователя:** My Profile → API Tokens → Create Token → Custom token;
   - **токен аккаунта (`cfat_…`):** Manage Account → Account API Tokens. Для него в «Настройки → Интеграции → Cloudflare» укажите ещё **Account ID**: он показывается при создании токена и справа на странице домена.

   Права токена: `Zone → Zone → Read` и `Zone → DNS → Edit` для нужных зон. Токен, созданный на странице R2, по умолчанию имеет только права R2: DNS он менять не сможет, и кнопка «Проверить» это покажет («не видит ни одной зоны").
   При каждой смене IP Cheker ставит у A-записи **серое облако** (proxied = false), даже если до этого было оранжевое.
2. **Remnawave.** В панели: Настройки → API Tokens → создать токен. Нужны URL панели и токен.
3. **Latency Lab.** Войдите на https://latencylab.ru/account.html через Telegram и создайте API-ключ (`ll_…`). Укажите его в «Настройки → Интеграции → Latency Lab».
   - Сначала пробуется `POST /api/lab/tspu` (результат «с провода»): `blocked: true` или `working: false` → бан.
   - Если ключу этот метод не разрешён (HTTP 403), используется `POST /api/lab/multiscan` с `tcp_port`, и смотрится поле `wire_ok`: `false` → бан, `true` → чисто. Если `wire_ok` не пришёл, IP считается в бане, когда порт недоступен у ≥50% мобильных операторов. `/tspu` пробуется снова раз в 6 часов.
   - Лимит: 1 проверка = 1 запрос из суточного лимита. Запросы идут по одному.
4. **bschekbot (дополнительный, необязательно).** Нужен тариф Bronze и выше. Ключ `bsk_live_…` создаётся в «Кабинет → API» на bsbord.com (показывается один раз). Укажите его в «Настройки → Интеграции → bschekbot» и включите источник в «Настройки → Источники».
   - Используется `POST /v1/probe` (синхронно) с целью `IP:порт`, только TCP-проба (`probes: {"tcp": true}`), с заголовком `Idempotency-Key`. Если ответ не успел (HTTP 524, 409 request_in_progress, лимиты), запрос повторяется **с тем же ключом**, поэтому второй раз деньги не списываются.
   - Проверка идёт через «единицы» `оператор|округ|БС`. По умолчанию `*|цфо|off`: все операторы ЦФО **без Белого списка**. С включённым Белым списком оператор режет почти все зарубежные IP, и результат был бы ложным. Набор единиц и фильтр БС меняются в настройках источника; там же список доступных сейчас единиц.
   - Бан — если порт недоступен у ≥50% единиц.
   - Каждая единица — отдельное списание (1 кредит = 1 копейка). Сколько списано, видно в деталях проверки IP; баланс — в статусе источника.
   - Если включены оба источника, IP считается заблокированным, когда его видит в бане **хотя бы один** из них.
5. **Telegram.** Создайте бота у @BotFather и напишите ему `/start`. Свой `chat_id` можно узнать у @userinfobot.
6. Домен для самой панели Cheker (например `cheker.example.com`): A-запись на IP VPS.

> Сервер с Cheker лучше держать **вне РФ**: из РФ запросы к Cloudflare API и Telegram сами могут упереться в блокировки.

## Запуск на VPS

```bash
git clone <repo> cheker && cd cheker      # или скопируйте папку
cp .env.example .env
nano .env                                  # заполните пароль, домен и токены
docker compose up -d --build
docker compose logs -f backend
```

Панель откроется на `https://PANEL_DOMAIN`.

Контейнеры:

| Контейнер | Что внутри | Порт внутри сети |
|---|---|---|
| `cheker-backend` | FastAPI + планировщик + SQLite | 8000 |
| `cheker-frontend` | nginx со собранным React | 80 |
| `cheker-caddy` | HTTPS, маршрутизация `/api/*` → backend, остальное → frontend | 80/443 наружу |

Пересобрать только одну часть: `docker compose up -d --build backend` или `docker compose up -d --build frontend`.

**Если на сервере уже работает Caddy или nginx** (например, на сервере с панелью Remnawave), порты 80/443 заняты. Тогда:
- удалите сервис `caddy` из `docker-compose.yml`;
- у `backend` замените `expose` на `ports: ["127.0.0.1:8000:8000"]`;
- у `frontend` замените `expose` на `ports: ["127.0.0.1:8080:80"]`;
- в существующий Caddyfile добавьте:
  ```
  cheker.example.com {
      handle /api/* {
          reverse_proxy 127.0.0.1:8000
      }
      handle {
          reverse_proxy 127.0.0.1:8080
      }
  }
  ```

Данные (SQLite) лежат в `./data/cheker.db`. Для бэкапа достаточно копировать эту папку.

## Как это работает

### Скорость нод
Скорость берётся из Remnawave при каждом опросе нод (раз в минуту): из realtime-статистики панели, если она есть, иначе по приросту счётчика трафика ноды (`trafficUsedBytes`).
- **Текущая скорость** — средняя за последние 5 минут.
- **Норма** — средняя за предыдущие 3 часа. После перезапуска Cheker она набирается заново, минимум 30 минут.
- **Падение** — текущая скорость меньше нормы на 70% и больше, и это держится 10 минут. Ноды с нормой меньше 1 Мбит/с не отслеживаются.

Все пороги меняются в «Настройки → Проверка». Текущая скорость и норма видны на вкладке «Ноды».

### Проверка IP после падения скорости
1. Для домена ноды запускается проверка: сразу, затем через 30 и через 60 минут (число проверок и интервал настраиваются).
2. Перед каждой проверкой читается актуальная A-запись в Cloudflare. Проверяется текущий IP через Latency Lab.
3. **Все 3 проверки показали бан** → IP помечается заблокированным. Резервные IP проверяются по порядку после текущего, по кругу, и A-запись переключается на первый доступный. Если доступных нет, приходит «Нет доступных IP».
4. **Хоть одна проверка показала, что IP доступен** → проверка сразу останавливается (так тратится меньше запросов), и приходит уведомление «С нодой что-то не так».
5. Ошибки проверки не засчитываются. Если за 6 попыток так и не удалось проверить IP, приходит уведомление об ошибке.
6. После завершения новая проверка того же домена начнётся не раньше чем через 3 часа.

Домены без привязанной ноды автоматически не проверяются. Их можно проверить вручную: кнопка «Проверить» (одна проверка) или «Запустить» в блоке «Проверка после падения скорости» (3 раза с интервалом).

### Добавление доменов
- **Вручную.** Нажмите «Добавить» и введите домен. Текущий IP определится сам (сначала A-запись в Cloudflare, потом DNS) и встанет первым в списке. Резервные IP можно добавить сразу или позже. Если ввести IP вместо домена, запись будет только мониториться.
- **Из Remnawave.** При каждом опросе нод Cheker проверяет их адреса. Если домена или IP ещё нет во вкладке «Домены», он добавится сам с пометкой «из Remnawave», и придёт уведомление. Выключается в «Настройки → Ноды Remnawave». Удалённый вручную домен заново из Remnawave не добавится.

### Уведомления в Telegram
Падение скорости ноды (начата проверка), «с нодой что-то не так», бан IP, разбан IP, автосмена, ручная смена, нет доступных IP, изменение A-записи вне панели, нода offline/online, ошибки API (Cloudflare, Remnawave, Latency Lab), блокировка входа при подборе пароля, ежедневная сводка. Каждое событие включается и выключается в Настройках.

### Защита входа
- Пароль из `APP_PASSWORD` (4–6 латинских букв/цифр).
- 5 неверных попыток с одного IP за 15 минут блокируют этот IP на 15 минут.
- 30 неверных попыток за час со всех IP включают глобальную блокировку на 30 минут (защита от перебора с разных адресов) и шлют уведомление в Telegram.
- Сессия хранится 7 дней в httpOnly-cookie.

## Как добавить новый источник проверки IP

1. Создайте `backend/app/checkers/my_source.py`:

```python
from app.checkers.base import BaseChecker, CheckResult
from app.checkers.registry import register_checker


@register_checker
class MySourceChecker(BaseChecker):
    name = "my_source"                 # уникальный id
    title = "Мой источник"             # название во фронте
    description = "Что проверяет"
    enabled_by_default = False

    async def check(self, ip: str, port: int | None = None) -> CheckResult:
        # self.options — настройки из панели (если источнику нужны свои параметры)
        resp = await self.client.get("https://example.com/api", params={"ip": ip})
        if resp.status_code != 200:
            return CheckResult(self.name, None, error=f"HTTP {resp.status_code}")
        data = resp.json()
        return CheckResult(self.name, blocked=bool(data["blocked"]), details={"raw": data})
```

2. Добавьте импорт в `backend/app/checkers/__init__.py`:

```python
from app.checkers import latencylab, my_source  # noqa: F401
```

3. Пересоберите контейнер. Источник появится в разделе «Настройки → Источники». Если включено несколько источников, IP считается заблокированным, когда его видит в бане хотя бы один из них.

## API (коротко)

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/login` | вход |
| GET | `/api/dashboard` | сводка для дашборда |
| GET/POST | `/api/domains` | список / создание домена (текущий IP определяется сам) |

| GET/PATCH/DELETE | `/api/domains/{id}` | домен |
| PUT | `/api/domains/{id}/ips` | заменить список IP (порядок важен) |
| POST | `/api/domains/{id}/switch` | ручная смена IP `{ "ip": "1.2.3.4" }` |
| POST | `/api/domains/{id}/check` | проверить домен сейчас (1 раз) |
| POST | `/api/domains/{id}/investigate` | запустить проверку N раз с интервалом |
| GET | `/api/investigations` | проверки после падения скорости |
| POST | `/api/investigations/{id}/cancel` | отменить проверку |
| GET | `/api/nodes` | ноды |
| POST | `/api/nodes/{uuid}/restart\|enable\|disable` | действия с нодой |
| GET | `/api/events` | журнал событий |
| GET/PUT | `/api/settings` | настройки |
| GET/PUT | `/api/settings/integrations` | токены и адреса интеграций |
| POST | `/api/settings/integrations/test/{group}` | проверить интеграцию |
| POST | `/api/system/check-now` | проверить все домены один раз |
| GET | `/api/tools/check-ip?ip=&port=` | проверить любой IP |
